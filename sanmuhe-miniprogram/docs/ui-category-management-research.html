商品「管理分类」交互调研

针对禾煦后台：商品管理 → 茶叶 →「管理分类」窄侧栏别扭问题 · 对照行业做法 · 给出推荐方案（先方案不改代码）

你的直觉是对的。

把「分类/集合」的增删改塞进商品列表旁边的窄抽屉，在主流电商后台里并不常见。 抽屉更适合「编辑当前商品」或「列表筛选」；分类本身是独立主数据，应有更宽的工作台或内嵌面板。

1. 当前问题（现状）

现在怎么做

  • 商品列表页工具栏：管理分类 按钮
  • 点开 → 右侧窄抽屉
  • 抽屉里：名称 / 排序 / 启停 + 表格
  • 商品编辑时再下拉选分类

为什么别扭

  • 信息架构错位：分类是「结构配置」，商品是「SKU 列表」，两者任务不同
  • 抽屉过窄：表格 + 排序 + 操作挤在一侧，难扫一眼
  • 上下文断裂：在列表上改分类，却看不到「每个分类有多少商品」
  • 入口权重：「管理分类」像临时工具，不像正式配置

2. 行业专业做法（调研结论）

综合 Shopify / 国内电商后台 / B 端组件规范（Modal vs Drawer）与信息架构常见模式：

模式 适用 行业例子 评价
独立「分类/集合」页 分类可增删改排序，需看商品数、启停 Shopify Collections、有赞/微商城「商品分类」菜单 最专业 主数据独立
商品页内嵌：顶栏/左侧分类树 + 列表 分类少（≤10）、以浏览筛选为主 多数中小电商后台「左侧分类 + 右侧商品」 很适合茶类 红茶/白茶…就几项
商品表单里选分类 + 内联「+新建」 只想快速加一个类名 Notion/部分 SaaS 的 create-on-the-fly 轻量 不替代完整管理
居中弹窗 Dialog 字段少、任务短（改名/排序一次搞定） Ant Design / Element 后台规范 可用 比窄抽屉宽
侧抽屉 Drawer 编辑「当前行商品」、筛选面板 Onething Design：Drawer 适合 filter / 上下文辅助 不适合当分类主台

Modal vs Drawer（组件选择原则）

  • Drawer：辅助当前页任务，不打断列表上下文（筛选、看详情、改一条商品）
  • Modal：短任务、需聚焦确认（新建一个分类名称）
  • 独立页 / 全宽工作台：字段多、要表格、要排序拖拽、要看关联数量 —— 分类管理属于这类

参考：Onething「Modal vs Drawer」、Eleken Modal UX、国内 B 端「列表 + 弹窗/独立页」通用模式。

3. 对照禾煦业务

茶叶分类

约 5 个：红茶、白茶、岩茶、普洱茶、单丛（+偶发自定义）

数量少、结构扁、几乎不嵌套 → 不必做复杂树。

堂饮档位

约 5 个：初见、知味…，且带价格/单位/主图

比茶叶「重」→ 更需要宽表编辑区（已是「管理档位」语义）。

4. 推荐方案（按优先级）

推荐首选 · A 商品页「分类条」+ 轻量管理面板（宽）

分类是导航/筛选，不是塞在窄抽屉里的次要按钮。

  1. 商品列表上方增加 分类 Tab / 胶囊条：全部 | 红茶 | 白茶 | …
  2. 条末放 「配置分类」（文案比「管理分类」更像设置）
  3. 配置打开 居中宽弹窗 或 全宽底部/居中 560–720px 面板，不是 280px 侧栏
  4. 面板内：表格（名称、排序、商品数、启停、操作）+ 顶部「添加分类」一行表单
  5. 商品编辑仍用下拉选分类；下拉旁可有「+」快速新建（可选）

备选 · C 侧栏一级菜单「商品分类」独立页

与「商品管理」并列：分类 CRUD 全页表格。Shopify Collections 思路。

最清晰，但多一个导航入口；茶类数量少时略重。

不推荐维持 窄右侧抽屉当分类主界面

与 Drawer 设计意图不符；表格与操作密度不匹配。

5. 若只改一刀（最小改动）

  1. 保留入口在商品页，但改成 居中 Dialog（宽 560–640px），不要窄 Drawer
  2. 表格增加「商品数」列（只读）
  3. 列表顶增加分类筛选胶囊（复用同一数据源）
  4. 文案：「管理分类」→「配置分类」或「分类设置」

成本低，能立刻消掉「窄侧栏」的别扭感，且符合「分类配置用聚焦面板」的惯例。
