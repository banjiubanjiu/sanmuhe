# 支付资金冻结防护（发货信息自愈与部署纪律）

> 背景：禾煦小程序属于「交易类小程序」，微信按《交易类小程序运营规范》对资金结算做担保管控——
> **商家录入发货信息（upload_shipping_info）后资金才进入结算周期**：快递 T+10、自提/虚拟 T+2（用户确认收货可立即结算）。
> 如果发货信息上传静默失败，钱会一直冻结在微信侧、不到银行卡。

## 一、曾发生的事故（2026-08 复盘）

- 08-19 部署把 `WX_MP_APPID` / `WX_MP_APPSECRET` 从云函数环境变量冲掉 → 云函数拿不到 access_token →
  会员充值的 `upload_shipping_info` 全部报 **10060001「支付单不存在」**（真实单也会报）→ 1000 元（08-22）+ 500 元（08-26）冻结 5 天+。
- 用商户证书调查单 API 证实：交易都在商户号 `1748659941` / appid `wx47e7cc7143682291` 下，钱没丢，只是没进结算周期。

## 二、已部署的防护（2026-08-27）

1. **自愈看门狗 `shippingWatchdog`**（云函数，定时 `0 */10 * * * * *` 每 10 分钟）：
   - 扫描 `orders` / `recharge_orders` / `reservations` 中「已微信支付、有 transactionId、`wxShippingUploaded != true`」的单，自动补传发货信息；
   - 拿不到 access_token（密钥被冲掉）→ 企业微信立即告警（30 分钟节流）；
   - 同一单连续失败 3 次 → 企业微信告警（每单最多 1 条/3 次失败）；
   - 测试单/不再重试的单：置 `wxShippingSkip: true` 跳过。
2. **三个支付相关云函数均已部署 `WX_MP_APPID` + `WX_MP_APPSECRET`**：
   `createPayment` / `wechatPayNotify` / `manageOperations`（manageOperations 额外保留了 ADMIN_* 权限配置）。

## 三、部署纪律（违反 = 重蹈覆辙）

- ❌ **禁止**用仓库 `sanmuhe-miniprogram/cloudbaserc.json` 对 `createPayment` / `wechatPayNotify` / `manageOperations` / `shippingWatchdog` 裸执行 `tcb fn deploy --force`（仓库配置不含密钥，会整份覆盖云端 env，冲掉 `WX_MP_APPSECRET` 与支付私钥）。
- ✅ 支付函数部署一律走：`./scripts/deploy-cloudfunctions-safe.sh --with-pay-secrets <函数名>`（自动从 `.secrets/wechat-pay.env` 注入密钥）。
- ✅ 看门狗部署：`tcb fn deploy shippingWatchdog --force -e <env> --config-file /tmp/watchdog.config.json`（含 WX_MP_* + WECOM_ORDER_WEBHOOK；配置生成见本目录 AGENTS.md 或按 `.secrets/wechat-pay.env` 重建）。
- ✅ 每次部署后自查：`tcb fn detail <函数名>` 里必须能看到 `WX_MP_APPSECRET=...`。

## 四、资金到账规则速查（回答"钱怎么还没到"）

| 订单类型 | 用户主动确认收货 | 系统自动结算 |
|---|---|---|
| 快递物流（茶叶配送） | 收货后立即 | 发货后 T+10 |
| 自提 / 堂饮 / 同城 | 收货后立即 | 发货后 T+2 |
| 虚拟（会员充值 / 茶室预约） | — | 发货后 T+2 |

- 用户侧确认收货在微信「订单/发货通知」里操作（小程序内"确认收货"只更新本地状态，不影响微信侧结算）。
- 若有纠纷投诉未解决，结算延后至纠纷解决。
