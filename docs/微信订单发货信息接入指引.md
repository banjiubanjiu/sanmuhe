# 微信小程序「订单管理-发货信息」接入指引

> 本文档说明禾煦小程序如何接入微信「订单管理-发货信息」（官方名称：**发货信息管理服务**）。
> 接入后：用户支付后，微信会向用户推送**订单发货通知**；用户点击通知进入小程序订单详情页，即可**查询物流轨迹、申请售后服务**，体验完整闭环。

---

## 1. 这是什么

微信「发货信息管理服务」是微信支付订单的能力：

- 用户交易后，微信按类目规则冻结资金，商家发货后在平台**录入发货信息**（`upload_shipping_info`）；
- 平台以消息形式把发货信息推送给购买用户（**订单发货通知**，无需订阅消息模板授权）；
- 商家设置**消息跳转路径**（`set_msg_jump_path`）后，用户点击通知直接进入小程序订单页；
- 小程序后台还提供「发货信息管理」页面，可**手动录入**发货信息（无 API 对接时兜底）。

官方文档：

- 发货信息录入 `upload_shipping_info`：
  https://developers.weixin.qq.com/miniprogram/dev/server/API/order_shipping/api_uploadshippinginfo.html
- 消息跳转路径设置 `set_msg_jump_path`：
  https://developers.weixin.qq.com/miniprogram/dev/server/API/order_shipping/api_setmsgjumppath.html

## 2. 代码已实现的部分（无需再开发）

| 业务线 | 触发时机 | `logistics_type` | 代码位置 |
| --- | --- | --- | --- |
| 快递发货（茶叶零售配送） | 后台订单管理点「标记发货」 | 1 实体快递 | `cloudfunctions/manageOperations/index.js` → `markShipped` |
| 到店自提 / 堂饮 | 微信支付成功回调 | 4 用户自提 | `cloudfunctions/wechatPayNotify/index.js` → `handleTransactionSuccess` |
| 茶室预约 | 微信支付成功回调 | 3 虚拟商品 | `cloudfunctions/wechatPayNotify/index.js` → `handleReservationSuccess` |
| 会员充值 | 微信支付成功回调 | 3 虚拟商品 | `cloudfunctions/wechatPayNotify/index.js` → `handleRechargeSuccess` |
| 手动重试上传 | 后台订单详情「同步微信发货」 | 按订单类型 | `manageOperations` → `retryWxShipping` |

通用实现：`cloudfunctions/{manageOperations,wechatPayNotify}/wechatShipping.js`

- 订单标识：优先用微信支付单号（`transaction_id`，`order_number_type=2`），缺失时回退商户单号（`mchid + out_trade_no`，`order_number_type=1`）；
- `delivery_mode=1`（统一发货，一笔订单一个物流单，官方枚举正确）；
- 顺丰快递自动传收件人掩码（`contact.receiver_contact`，后 4 位不打码）；
- 幂等：已上传（`wxShippingUploaded=true`）或微信返回 `10060002 已完成发货` 时不再重复上传；
- 上传结果写回订单文档（`wxShippingUploaded / wxShippingError / wxShippingLogisticsType` 等），后台订单详情可查并重试。

小程序端：

- 订单详情页 `pages/order-detail/index`：物流轨迹查询（含缓存、刷新）、复制单号、申请售后、确认收货；
- 云函数 `listMyRecords`：`getOrder` 支持按本地 `_id`、`orderNo`、`transactionId` 查询（本次新增后两种）。

## 3. 本次新增的部分

1. **消息跳转路径**（`set_msg_jump_path`，本次接入的关键一环）

   - 云函数 `manageOperations/wechatShipping.js` 新增 `setMsgJumpPath(cloud, path)`，支持 openapi 云调用与 HTTPS 两种方式；
   - `manageOperations` 新增 action：
     - `setWxShippingJumpPath`：把跳转路径同步到微信并记录审计（路径默认 `pages/order-detail/index`）；
     - `getWxShippingStatus`：诊断查询——是否已开通发货信息管理、是否完成交易结算管理确认、跳转路径是否已同步。
   - 微信会在跳转路径后自动附加 `transaction_id`、`merchant_id`、`merchant_trade_no`（二级商户另有 `sub_merchant_id`）。

2. **落地页按微信参数解析订单**

   - `pages/order-detail/index.js`：`onLoad` 无本地 `id` 时，解析微信附加的 `transaction_id / merchant_trade_no / out_trade_no`，通过 `listMyRecords.getOrder` 反查本地订单；
   - `utils/cloudApi.js`：`getMyOrder(orderId, lookup)` 支持传 `transactionId / orderNo`。

3. **管理后台设置页**（「设置管理 → 订单与履约 → 微信发货信息管理」）

   - 展示接入状态（发货信息管理是否开通 / 交易结算确认是否完成 / 跳转路径是否同步）；
   - 可编辑「发货通知跳转页」并一键「同步跳转路径到微信」；
   - 设置项落库：`store_settings.wxShippingJumpPath`、`wxShippingJumpPathSynced`。

## 4. 微信侧必须的人工配置（上线前）

> 以下步骤无法通过代码完成，需登录对应平台操作。**未完成前接口会报错或跳转不生效。**

1. **开通「发货信息管理服务」**

   微信公众平台 → 小程序后台 →「支付与交易 / 功能」→「订单管理 / 发货信息管理」，按页面提示开通（无 API 对接时也可以直接在该页面手动录入发货信息）。

2. **完成「交易结算管理确认」**

   微信支付商户平台（pay.weixin.qq.com）首次使用需完成**交易结算管理确认**授权（商户号关联 AppID）。状态可用后台「刷新接入状态」验证，对应接口 `is_trade_management_confirmation_completed`。

3. **云函数 openapi 权限**

   微信开发者工具 → 云开发控制台 → 云函数 → `wechatPayNotify` 与 `manageOperations` → 权限设置，确认已包含（云调用需要）：

   - `wxa.sec.order.uploadShippingInfo`（发货信息录入，权限集 142）
   - `wxa.sec.order.setMsgJumpPath`（消息跳转路径设置）
   - 查询状态可选：`wxa.sec.order.isTradeManaged`、`wxa.sec.order.isTradeManagementConfirmationCompleted`

   > 若云开发环境未自动注入 `ACCESS_TOKEN`，`wechatShipping.js` 会走 HTTPS 直调并尝试 `cloud.openapi.auth.getAccessToken()`，两种方式至少需配置其一。

4. **配置「订单详情页 PATH」（开发平台）**

   微信公众平台 / 商户平台的「订单管理」配置项中，若要求填写**订单详情页 PATH** 且提示「PATH 需包含 `${商品订单号}`」，按如下填写（`${商品订单号}` 占位符原样保留，微信会把你支付预下单时填入的 `out_trade_no` 替换进去，`out_trade_no` 即本地订单号 `orderNo`）：

   ```
   pages/order-detail/index?orderNo=${商品订单号}
   ```

   - 不要替换成真实单号，也不要加前导 `/`；该配置最多 1 条；
   - 该配置与第 3 节「发货通知跳转路径」（`set_msg_jump_path`）是**两个不同的配置项**：发货通知跳转页不填占位符，由微信自动附加 `transaction_id` 等参数；
   - 落地页 `pages/order-detail/index` 已支持解析 `orderNo` 参数反查本地订单，无需再开发。

5. **微信支付环境变量**

   确认 `wechatPayNotify` / `manageOperations` 已配置 `WECHAT_PAY_MCH_ID` 等支付环境变量（商户单号回退时需要 `mchid`）。

## 5. 部署步骤

```bash
# 1) 部署云函数（wechatPayNotify / manageOperations / listMyRecords 必须）
./deploy-cloudfunctions.sh <envId>

# 2) 构建并验证经营后台（产物在 admin-panel/admin，部署到 CloudBase 静态托管）
cd sanmuhe-miniprogram && npm run admin:verify

# 3) 小程序端随正式包提审（订单详情页含物流/售后）
```

## 6. 后台操作（一次性）

1. 登录经营后台 →「设置管理」→「订单与履约」→「微信发货信息管理」；
2. 点「刷新接入状态」：确认三项均为已开通/已完成；
3. 确认「发货通知跳转页」为 `pages/order-detail/index`（默认值）；
4. 点「同步跳转路径到微信」，显示成功即可。

---

## 7. 验证清单（真机）

1. 真机微信支付一笔**快递配送**订单；
2. 经营后台订单管理 → 该订单 → 填写快递公司与单号 →「标记发货」；
3. 微信「服务通知」收到**订单发货通知**（由平台推送，无需订阅授权）；
4. 点击通知 → 进入小程序订单详情页（自动定位该订单，无需再次查找）；
5. 页面展示快递公司、单号、「刷新轨迹」可查看最新物流节点；
6. 页面可「申请售后」填写原因，店员在后台售后列表处理；
7. 自提 / 堂饮 / 预约 / 充值订单：支付成功后微信侧即记为已发货（不产生快递通知），用户仍可在小程序内查看订单状态。

## 8. 常见报错与排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `48001 api unauthorized` | 云函数 openapi 未授权 `wxa.sec.order.*`，见第 4 节第 3 步 |
| `10060001 支付单不存在` | `transaction_id`/`out_trade_no` 与微信侧不一致，检查支付环境变量与订单落库字段 |
| `10060002 已完成发货` | 正常幂等（已处理为成功），无需处理 |
| `10060003 已使用重新发货机会` | 同一支付单已重发一次，不能再改发货信息 |
| `10060031 支付单不属于该 openid` | `payer.openid` 与支付用户不一致，检查 `_openid` 落库 |
| 后台显示「未开通 / 未完成」 | 未完成第 4 节第 1、2 步的微信侧人工配置 |
| 收到通知但点击无跳转 | 未执行「同步跳转路径到微信」，或路径在小程序中不存在（微信将跳平台默认页） |

## 9. 可选增强（后续需要时再做）

- **确认收货组件**：小程序接入微信 `<confirm-order-button>`（基础库 3.2.0+），用户在微信侧确认收货，资金解冻结算更及时；当前小程序内「确认收货」仅更新本地订单状态。
- **`notify_confirm_receive`**：物流签收时服务端调用，微信提醒用户确认收货。
- **消息推送事件**：配置小程序「消息推送」到云函数，接收 `trade_manage_remind_shipping`（提醒发货）等事件，用于店员催发提醒。
- **分拆发货**（`delivery_mode=2`）：一笔支付单多个包裹时使用，当前业务无需。
