## 2. 业务范围：何谓「正式上线」

以 `PRODUCT.md`、`sanmuhe-miniprogram/README.md`、生产/迁移清单与根目录 `问题` 为准，正式上线至少应让真实顾客在**无需询问店员**的情况下完成：

| 旅程 | 预期 | 当前实现概览 |
| --- | --- | --- |
| 首页了解门店 | 云内容 + 本地兜底 | 有 `getCatalog` / 本地 catalog |
| 堂饮点单（含桌号扫码） | 下单 → 支付/到店确认 → 店员履约 | 桌号解析在 `app.js`/`utils/table.js`；订单云函数完备度高 |
| 茶叶购买 | 购物车 → 微信/余额支付 → 发货/自提 | 支付链路依赖真实商户配置；发货信息上传微信侧未见实现 |
| 茶室预约 | 选时 → 提交 → 确认/支付规则清晰 | 落库默认 `待支付`；**是否先付费**仍为产品未决（见 `问题` #1） |
| 活动报名 | 报名 → 确认/收费规则清晰 | 报名「待确认」；**无在线收费**；任意用户可「发布活动」 |
| 会员储值 | 开通 → 充值 → 余额消费 | 真支付开关与测试模拟并存，生产危险 |
| 我的记录 / 客服 | 订单预约可查、客服可达 | 有 contact / open-type contact；客服电话疑似占位 |
| 经营后台履约 | 登录、接单、改状态、备份、隐私删除 | 后台构建在 `admin-panel/`；verify 仍指向旧路径 |

## 6. Bugs 与缺陷清单（代码/配置）

> 每条至少一条路径 + 失败模式。Severity 与上线关系见上节。

### BUG-1 全员模拟充值（资金逻辑缺陷）— Confirmed

- **路径**：`sanmuhe-miniprogram/cloudfunctions/memberCenter/index.js`（`isTestOpenid`，约 L164–180）  
- **现象**：`MEMBER_TEST_MODE=true` 且 `MEMBER_TEST_STRICT` 非 `"true"` 时，**任意 openid** 可走模拟充值入账。  
- **配置**：`cloudbaserc.json` memberCenter：`MEMBER_TEST_MODE=true`，`MEMBER_TEST_STRICT=false`。  
- **风险**：伪造余额 → 真实商品/服务被 0 成本兑付。

### BUG-2 真实支付开关与密钥配置不一致 — Confirmed

- **路径**：`sanmuhe-miniprogram/cloudbaserc.json` → `createPayment.envVariables`  
- **现象**：`REAL_PAYMENT_ENABLED=true`，但 CERT_SERIAL / PRIVATE_KEY / API_V3_KEY / 平台公钥|证书均为 **MISSING**（本文件内）。  
- **对照**：`createPayment/index.js` `paymentConfigHealth()` 将上述项列为 ready 必要条件。  
- **风险**：配置漂移；未在控制台补齐则支付必失败；若只在控制台有密钥则仓库失去可复现真相。

### BUG-3 顾客文案泄露实现细节 — Confirmed

- **路径**：`pages/member/index.wxml` L115；`pages/member/index.js` 支付失败/未配置 modal（约 L457）
